# 项目后mortem

## 当初这个项目想解决什么问题（一句话）
搭建一个像Ruoyi一样的快速开发平台，解决Ruoyi的一些硬伤，同时将搭建的过程完整录屏，分享给其他开发者。

## 它死在了哪一步（具体、技术性的，不是“没时间”）
1. 我使用了Vuestic Admin作为前端模板，但是我没有完成前端页面的搭建。因为我不擅长做界面，不能完整做出来符合审美标准的页面。
2. 低估了完成一个整体平台的工作量。
3. 对一个完整平台需要哪些东西还是不甚了解，没有做好详细的规划。
4. 埋没于过多的细节中。

## 如果再来一次，我会直接删掉的三件东西
1. 去掉前端部分，或者使用成熟的有现成界面的前端模板。
2. 不应该把xxl-job作为一个组件集成到项目中，它太重了。应该使用quartz等轻量级的定时任务调度器自己定义界面。
3. 考虑这种东拼西凑的合理性，是否真的需要一个快速开发平台？也许本项目本身就应该删除。


## 这个项目已经为我提供了什么（哪怕只是“我再也不会用 X 技术做 Y 了”）
1. 搭建一个快速开发平台的基本过程。
2. Spring security的用法，怎么合理的嵌套到系统中。
3. 简单的前端以及前端后端交互方式。
